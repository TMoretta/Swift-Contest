\chapter{Tecnologie e strumenti utilizzati}\label{ch:tecnologie-e-strumenti-utilizzati}

La realizzazione del progetto \textbf{Swift Contest} è stata resa possibile dall'adozione di un insieme di tecnologie, piattaforme e strumenti moderni, selezionati per soddisfare i requisiti di cross-platform, sicurezza, scalabilità e velocità di sviluppo.
Questo capitolo descrive lo stack tecnologico utilizzato, giustificando le scelte chiave in relazione agli obiettivi del progetto.

\section{Framework, piattaforme e linguaggi}\label{sec:linguaggi-framework-piattaforme}
Questa sezione descrive le tecnologie fondamentali su cui si basa l'architettura software del progetto, partendo dal frontend fino ad arrivare ai linguaggi di programmazione utilizzati.

\subsection{Framework Frontend}\label{subsec:framework-frontend}

\techitem{capitoli/figure/logos/flutter}{Flutter~\cite{flutter_docs}}{
    è il framework UI open-source di Google scelto per lo sviluppo dell'applicazione client.
    La sua caratteristica principale è la capacità di generare applicazioni compilate nativamente per mobile, web e desktop da un'unica codebase.
    Questa scelta è stata fondamentale per soddisfare il requisito di \textbf{sviluppo cross-platform}, garantendo un'esperienza utente coerente e riducendo drasticamente i tempi di sviluppo e manutenzione.
}

\vspace{1em}

\subsection{Framework e piattaforme Backend}\label{subsec:framework-e-piattaforme-backend}

\techitem{capitoli/figure/logos/supabase}{Supabase~\cite{supabase_docs}}{
    è la piattaforma open-source \textbf{Backend-as-a-Service (BaaS)} che costituisce il cuore dell'infrastruttura server.
    La scelta è ricaduta su Supabase dopo un'attenta valutazione delle principali alternative, in particolare \textbf{Firebase}~\cite{firebase_docs} di Google.
    Supabase è stato preferito per una ragione architetturale fondamentale: il suo backend è interamente basato su \textbf{PostgreSQL}.
}

\techitem{capitoli/figure/logos/postgresql}{PostgreSQL~\cite{postgresql_docs}}{
    è il potente sistema open-source per la gestione di database relazionali su cui si basa l'intera piattaforma Supabase. La decisione di adottare un backend basato su SQL, e in particolare su PostgreSQL, è stata un fattore determinante nella scelta tecnologica, in quanto garantisce integrità referenziale e la possibilità di eseguire query complesse, a differenza delle alternative basate su database NoSQL come Firebase.
}

\vspace{1em}

\subsection{Linguaggi di programmazione}\label{subsec:linguaggi-di-programmazione}

\techitem{capitoli/figure/logos/dart}{Dart~\cite{dart_docs}}{
    è il linguaggio di programmazione su cui si basa il framework Flutter. Essendo una conseguenza diretta della scelta di Flutter, le sue caratteristiche si sono rivelate ideali per gli obiettivi del progetto: è un linguaggio moderno, orientato agli oggetti e fortemente tipizzato, la cui architettura supporta sia la compilazione \emph{Just-In-Time (JIT)} per uno sviluppo rapido (con \emph{hot reload}), sia la compilazione \emph{Ahead-Of-Time (AOT)} per garantire performance elevate in produzione.
}

\techitem{capitoli/figure/logos/typescript}{TypeScript~\cite{typescript_docs}}{
    è il linguaggio richiesto dal runtime Deno per lo sviluppo delle \textbf{Edge Functions} su Supabase.
    Sebbene non sia stata una scelta attiva, la sua natura fortemente tipizzata, unita alla vasta disponibilità di librerie dell'ecosistema JavaScript, si è rivelata ideale per orchestrare le interazioni sicure con le API di servizi esterni.
}

\techitem{capitoli/figure/logos/postgresql}{PL/pgSQL~\cite{postgresql_docs}}{
    è il linguaggio procedurale nativo di PostgreSQL. È stato utilizzato per scrivere tutte le \textbf{Funzioni RPC (Remote Procedure Call)} del sistema, una scelta che si è rivelata fondamentale per garantire l'atomicità delle operazioni complesse e per ottenere performance elevate.
}

\vspace{1em}

\section{Strumenti, servizi e piattaforme di supporto}\label{sec:strumenti-servizi-piattaforme-supporto}
Questa sezione descrive le piattaforme di terze parti e gli strumenti che hanno supportato il ciclo di vita del progetto.

\subsection{Piattaforme di distribuzione e servizi Cloud}\label{subsec:piattaforme-di-distribuzione-e-servizi-cloud}

\techitem{capitoli/figure/logos/vercel}{Vercel~\cite{vercel_website}}{
    è la piattaforma serverless utilizzata per la distribuzione e l'hosting della versione \textbf{Web} dell'applicazione Flutter.
    La scelta è ricaduta su Vercel principalmente per il suo \textbf{piano gratuito} e per una pipeline di \textbf{CI/CD} completamente automatizzata.
}

\techitem{capitoli/figure/logos/resend}{Resend~\cite{resend_website}}{
    è il servizio transazionale di invio \textbf{email} utilizzato dal sistema, integrato tramite la propria API REST per gestire l'invio di tutte le email automatiche.
}

\techitem{capitoli/figure/logos/google-cloud}{Google Cloud}{
    è stato utilizzato per uno dei suoi servizi API: la \textbf{Google Places API}~\cite{google_places_api_docs}.
    Questo servizio è stato integrato per fornire la funzionalità di ricerca e autocompletamento degli indirizzi.
}

\vspace{1em}

\subsection{Strumenti di sviluppo e amministrazione}\label{subsec:strumenti-di-sviluppo-e-amministrazione}

\techitem{capitoli/figure/logos/intellij}{IntelliJ IDEA~\cite{intellij_idea_website}}{
    è l'IDE di JetBrains utilizzato per la scrittura del codice.
    Si è scelto di migrare da \textbf{Android Studio} a \textbf{IntelliJ IDEA Community Edition} per una maggiore stabilità e reattività.
}

\techitem{capitoli/figure/logos/npm}{Node Package Manager (npm)~\cite{npm_website}}{
    è stato uno strumento indispensabile per l'installazione e la gestione di dipendenze di sviluppo, prima tra tutte la \textbf{CLI di Supabase}.
}

\techitem{capitoli/figure/logos/retool}{Retool~\cite{retool_website}}{
    è la piattaforma \emph{low-code} utilizzata per costruire rapidamente la \textbf{dashboard di amministrazione} interna.
}

\vspace{1em}

\subsection{Version Control e Code Hosting}\label{subsec:version-control-e-code-hosting}

\techitem{capitoli/figure/logos/git}{Git~\cite{git_website}}{
    è il sistema di \textbf{controllo di versione distribuito} utilizzato per tracciare ogni modifica al codice sorgente del progetto.
}

\techitem{capitoli/figure/logos/github}{GitHub~\cite{github_website}}{
    è la piattaforma di \textbf{code hosting} che ospita il repository Git del progetto, integrata con la pipeline di CI/CD di Vercel.
}

\vspace{1em}

\subsection{Strumenti di documentazione e modellazione}\label{subsec:strumenti-di-documentazione-e-modellazione}

\techitem{capitoli/figure/logos/plantuml}{PlantUML~\cite{plantuml_website}}{
    è lo strumento open-source utilizzato per creare tutti i diagrammi UML e architetturali.
    La sua caratteristica distintiva è l'approccio ``diagrams as code'': i diagrammi vengono descritti attraverso un \textbf{linguaggio DSL (Domain-Specific Language)} testuale.
}
